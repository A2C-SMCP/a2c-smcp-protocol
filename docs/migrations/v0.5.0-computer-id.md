# v0.5.0 迁移指南：Computer 稳定身份 `computer_id`

> **状态**：`0.5.0-dev`（开发中，未发布）。协议尚未正式上线，无存量兼容包袱，**不设迁移期、不提供双模式开关**。

## 一句话

v0.5.0 起 Computer 入房 **MUST** 携带持久化的随机 UUID `computer_id`；Server 校验、记录并在成员通知与 `server:list_room` 中回显。`name` 只作展示与路由地址，不再被宿主误当机器身份。这是一次**破坏性**线上变更（`EnterOfficeReq` 新增条件必填字段）。

关联：a2c-smcp-protocol#64（裁决：[issuecomment-6359573953](https://github.com/A2C-SMCP/a2c-smcp-protocol/issues/64#issuecomment-6359573953)）；依赖方 #65（按路径读取）。

## 为什么改

宿主需要持久引用 Computer 本地文件（如 `computer://<computer_id>/<path>`）。`name` 由用户自取、仅房内唯一——新机器沿用旧名时，宿主会**静默读到另一台机器同路径下的不同文件**；`sid` 每次连接都变。两者都不能充当机器身份。

## 规则变化

| 项 | v0.4.x | v0.5.0 |
|---|---|---|
| `EnterOfficeReq.computer_id` | 无 | `role="computer"` **MUST** 携带；`role="agent"` **MUST NOT** 携带 |
| 形态 | — | 小写规范 UUID 文本（`8-4-4-4-12`），v4 / v7 生成，接收方视为不透明 |
| 缺失 / 非法 / Agent 携带 | — | `400` |
| 同一会话改变 `computer_id` | — | `403`（与 role / name 身份一致性同规则）|
| `notify:enter_office` / `notify:leave_office` | `office_id` / `computer` / `agent` | 增加 `computer_id`（成员为 Computer 时）|
| `SessionInfo` | 无 | 增加 `computer_id`（`role="computer"` 时）|
| 冲突检测 | — | **无**：Server MUST NOT 因 `computer_id` 重复拒绝；跨房克隆识别归宿主 |
| 新错误码 | — | **无**（复用 `400` / `403`）|

## 各角色需要做什么

### Server（SDK）

1. `server:join_office` 载荷校验：按上表回 `400`；同一 sid 的 `computer_id` 与已记录值不同回 `403`。均先于席位检查。
2. 入房成功后记录 `computer_id`，在 `notify:enter_office` / `notify:leave_office`（含断连、自动换房）与 `SessionInfo` 中原样回显。
3. 不建立跨房 `computer_id` 索引，不据重复拒绝。
4. 覆盖 [房间模型 §一致性测试场景](../specification/room-model.md#一致性测试场景) #10–#16。

### Computer（SDK）

1. 首次启动生成 UUID v4/v7（**不得**由 MAC / machine-id / 硬件指纹派生），持久化在 Computer 侧（位置 SDK 自治），跨重启复用。
2. 每次 `server:join_office` 携带同一值。
3. 提供显式「重置身份」入口：生成新值并持久化；已连接时须断连并以新连接入房（连接内改变会被 `403`）。

### Agent（SDK / 宿主）

- 从 `notify:enter_office` / `SessionInfo` 读取当前在房 Computer 的 `computer_id`，用于判定持久引用是否指向当前 Computer。
- Agent 入房**不得**携带 `computer_id`。
- 克隆（同一 `computer_id` 出现在两台机器）的识别与处置属宿主职责，见 [房间模型 §Computer 身份](../specification/room-model.md#computer-身份)。
