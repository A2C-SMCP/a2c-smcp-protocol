# v0.5.0 迁移指南：按路径读取 `client:resolve_path` + `readRoots`

> **状态**：`0.5.0-dev`（开发中，未发布）。协议尚未正式上线，无存量兼容包袱，**不设迁移期、不提供双模式开关**。

## 一句话

v0.5.0 新增 `client:resolve_path`：Agent 给出 Computer 本地路径，Computer 在用户授权的 `readRoots` 内规范化、stat 并**现铸** `blob_handle`，字节仍经 `client:get_blob` 拉取。新增错误码 `4020`；`4018` 枚举不变；新增 settings 键 `readRoots`（默认空 = 不可读）。宿主持久引用 = `computer_id` + `canonical_path`。

关联：a2c-smcp-protocol#65（裁决：[issuecomment-6359575117](https://github.com/A2C-SMCP/a2c-smcp-protocol/issues/65#issuecomment-6359575117)）；前置 #64（`computer_id`）。

## 为什么改

宿主（如 TFRobotServer）要在文档与会话中持久引用 Computer 本地文件。`client:get_blob` 只认生产者铸造的短时句柄（SKILL / tool_call），没有按路径读取的能力，句柄也不能持久化。新增生产者事件而非新 handle kind：Agent 不得自行构造句柄（[BlobHandle 契约](../specification/blob-transfer.md#1-blobhandle-契约)）。

## 规则变化

| 项 | v0.4.x | v0.5.0 |
|---|---|---|
| 按路径读取 | 无 | `client:resolve_path(path)` → `canonical_path` / `total_size` / `sha256` / `mime_type` / `mtime` + 现铸 `blob_handle` |
| 授权边界 | — | settings `readRoots: list[str]`；**默认空 = 不可读**；仅受信 scope，`project` scope MUST 拒绝 |
| 固定拒绝集 | — | `.skillenv` / Computer 配置·状态·凭据目录 / `.part` 即便在 `readRoots` 内也 `forbidden` |
| 铸造期错误 | — | **新码 `4020`**：`invalid_path` / `forbidden` / `not_found` / `not_a_file` |
| 拉取期错误 | `4018` | `4018` **枚举不变**：撤权 → `forbidden`，删除 → `gone` |
| 路径表示 | — | `normalize_path` 纯函数 + [数据向量](../specification/fixtures/canonical_path_conformance_vectors.json)：POSIX 绝对；Windows `/C:/...`、盘符大写、`/` 分隔；不做百分号编码 |
| 大文件 | — | 不设上限；`sha256` 必返，受常规请求超时；MAY 按 `(canonical_path, total_size, mtime)` 缓存 |
| `blob-transfer §1`「非任意文件读」/ `skill.md §9.2` | 只服务生产者已授权的源 | 措辞同步：path 生产者的授权边界 = `readRoots` |

## 各角色需要做什么

### Computer（SDK）

1. 实现 `client:resolve_path`，处理顺序严格按 [§Computer 处理流程](../specification/blob-transfer.md#computer-处理流程)：`normalize_path`（`..` 词法消解）`invalid_path` → `readRoots` 空 / 词法越界 `forbidden`（不访问文件系统）→ **非严格** realpath（`lstat` + `readlink`，悬空链接照样解析）越界 `forbidden`（此前任何文件系统错误都归 `forbidden`）→ 固定拒绝集 `forbidden` → 打开前 `lstat` 预检：不存在 `not_found`、非普通文件 `not_a_file` → 非阻塞打开：`ENOENT`/`ENOTDIR` `not_found`、`EISDIR` `not_a_file`、其余 `forbidden` → 同一句柄 stat / sha256 / 确定性 MIME → 铸造句柄。
   固定拒绝集：`.skillenv`、本 SDK 的配置 / 状态 / 凭据目录、未定稿 `.part`——即便在 `readRoots` 内也拒绝。
2. `normalize_path` 以纯函数实现，逐字节通过 vendored 数据向量（含 `windows` 平台向量，在任意 OS 上测）。
3. settings 新增 `readRoots`：绝对路径列表；每个 root 保留**配置形态**与 **realpath 形态**（词法围栏任一命中，realpath 围栏只认后者）；`project` scope 提供则整字段不生效；围栏按路径分量判定。
4. path 句柄编码 `canonical_path` + stat 键 + `sha256`。`client:get_blob` 解析时按**当前** `readRoots` 重跑围栏 / 拒绝集 / 权限校验：越界或撤权 → `4018 forbidden`；删除 / 非普通文件 / stat 键不符（已改写）→ `4018 gone`；相符则直接回填句柄内的 `sha256`，不重算。
5. 覆盖 [conformance §2.8 / §4.5](../specification/computer-management/conformance-tests.md#28-canonical_path-路径规范化)。

### Server（SDK）

- 按 `computer` 路由 `client:resolve_path`（与其它 `client:*` 相同），无其它变化。

### Agent（SDK / 宿主）

- 持久化 `computer_id` + `canonical_path`，**不**持久化 `blob_handle`；每次读取先确认当前在房 Computer 的 `computer_id`，再 resolve → `get_blob`。
- 只需变更检测时比对 `ResolvePathRet.sha256`，不必拉字节；`get_blob` 的 `sha256` 与 resolve 时不同 ⇒ 文件已改写，重新 resolve。
- `4020 forbidden` 提示用户在 Computer 端配置 `readRoots`；`not_found` / `not_a_file` 如实呈现。
- `computer://` URI 的组装与 RFC 3986 百分号编解码属宿主。
