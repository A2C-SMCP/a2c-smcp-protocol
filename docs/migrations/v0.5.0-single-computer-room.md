# v0.5.0 迁移指南：一房至多一台 Computer

> **状态**：`0.5.0-dev`（开发中，未发布）。协议尚未正式上线，无存量兼容包袱，**不设迁移期、不提供双模式开关**。

## 一句话

v0.4.x 允许「1 Agent + 任意多 Computer」同房；v0.5.0 收紧为 **「每 role 一席」——一房至多 1 Agent、至多 1 Computer**。由于 Agent 同一时刻只能在一个房间，这等价于 **一个 Agent 同一时刻至多与一台 Computer 连接**。这是一次**破坏性**成员规则变更。

关联：a2c-smcp-protocol#66（另见 #64 `computer_id`、#65 按路径读取）。

## 为什么改

宿主把 Computer 当作 Robot 的**运行环境**：bash 封装、普通文件路径都解析到「当前这台 Computer」，持久引用形如 `computer://<computer_id>/<path>`。这一模型要求 Agent 任意时刻只面对一台 Computer——否则每条路径、每次命令都要带上 Computer 选择，或在多台之间猜测，把歧义推给 LLM。多 MCP 服务的聚合本就在单个 Computer 内部完成；横向扩展改由**多房间**承担。

## 规则变化

| 项 | v0.4.0（已发布）| v0.5.0 |
|---|---|---|
| 房内 Computer 数 | 不限 | **至多 1** |
| 第二台 Computer 入房 | 成功 | **拒绝 `4101`**，`details.role = "computer"`；**不替换**旧 Computer |
| 同 role 同名入房 | 未规定 | **`4101`**（席位检查覆盖同名）|
| join ack 失败形态 | `(bool, str \| None)` 元组 | flat `ErrorPayload`（Discussion#61 裁决，同属 0.5.0）|
| `4101` | 「房间已有 Agent」 | 「本 role 席位已占」，`details`: `office_id` / `role` |
| `4105 Name Conflict` | 不存在 | **预留码**，SDK MUST NOT 返回 |
| 换绑 Computer | — | 旧 Computer 离房 → 新 Computer 入房（既有 `notify:leave_office` → `notify:enter_office`），**无新事件** |
| 能力声明 | — | **无**（随 0.5 MINOR 版本握手生效，不加 `single_computer` 字段）|

> `4105` 仅出现在 0.5.0-dev 草案（Discussion#61 / PR#62，表示「房内同 role 同名」），发布前即随本变更转为预留——**0.4.0 代码中没有需要移除的 4105 处理**；若 SDK 已按草案实现了 4105 产出，改为 `4101` 即可。

`client:*` 的 `computer` 路由字段**保持不变**；Server 仍按 `(office_id, "computer", name)` 解析并校验。

## 各角色需要做什么

### Server（SDK）

1. `server:join_office` 的 Computer 分支：在**任何副作用之前**做席位检查——目标房已有 Computer 且非本会话 ⇒ `4101 {office_id, role: "computer"}`；通过后才执行「自动离开旧房」。
2. Agent 分支的 `4101` `details` 补 `role: "agent"`。
3. 不产出 `4105`（若已按 0.5.0-dev 草案实现，移除）。
4. 「席位检查 + 占席」对同一 `office_id` 原子；幂等重入不重复广播 `notify:enter_office`。
5. 覆盖 [房间模型 §一致性测试场景](../specification/room-model.md#一致性测试场景) 全部用例。

### Computer（SDK）

- 把 `4101` 视为「目标房已有其它 Computer」：仅在**刚经历传输层重连**时做有界退避重试，否则如实报错（不改名重试——改名无效）。

### Agent（SDK / 宿主）

- 可假定任一时刻房内至多一台 Computer：移除「遍历 / gather 房内全部 Computer」的逻辑（工具聚合、SKILL、Desktop）。
- 收到 `notify:leave_office(computer=X)` 清理 X 的全部缓存；随后 `notify:enter_office(computer=Y)` 即换绑完成，重新拉取。
- 对旧 Computer 的持久引用（`computer://<旧 id>/…`）如何呈现（如 `offline`）属宿主语义，协议不会把它转发给新 Computer。
